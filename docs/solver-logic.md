# 定時退社タンゴ ― ソルバーロジック & パズル設計指針

最終更新: 2026-05-04

---

## 1. ゲームルール（前提）

- **グリッドサイズ**: 6×6（将来は4×4, 8×8も検討）
- **記号**: 👔（出社=1）と 🍺（退社=2）の2種類
- **ルール①**: 各行・各列に 👔 と 🍺 が**ちょうど3個ずつ**
- **ルール②**: 同じ記号が**3連続してはいけない**（行・列どちらも）
- **ルール③**: セル間の制約
  - `=` マーク: 隣接する2セルは**同じ記号**
  - `×` マーク: 隣接する2セルは**異なる記号**

---

## 2. 解法パターン一覧

### レベル1 ― 単発強制（1ステップで確定）

これらのみで解けるパズルを **初級** とする。

---

#### ① バランス完了 (Balance Completion)

行または列にすでに n/2 個の同じ記号がある場合、残りの空セルは全て逆の記号に確定する。

```
[👔 🍺 _ _ 👔 👔]
→ 👔 が3個 → 残り全て 🍺
→ [👔 🍺 🍺 🍺 👔 👔]
```

**検出条件**: `count(記号X, 行/列) == 3` かつ 空セルがある

---

#### ② ダブルブロック (Double Block)

同じ記号が2連続している場合、その隣（前後）は必ず逆の記号になる。

```
[👔 👔 _ ...]  →  [👔 👔 🍺 ...]
[... _ 🍺 🍺]  →  [... 👔 🍺 🍺]
```

**検出条件**: `grid[i] == grid[i+1] != EMPTY` → `grid[i-1]` と `grid[i+2]` を逆に確定

---

#### ③ サンドイッチ (Sandwich)

同じ記号に1つ挟まれている場合、中間セルは逆の記号に確定する。

```
[👔 _ 👔]  →  [👔 🍺 👔]
（中間を👔にすると [👔 👔 👔] で3連続違反）
```

**検出条件**: `grid[i] == grid[i+2] != EMPTY` かつ `grid[i+1] == EMPTY`

---

#### ④ 制約直接 (Direct Constraint)

`=` または `×` の制約で、片方が確定している場合、もう片方が強制される。

```
= 制約: [👔 = _]  →  [👔 = 👔]
× 制約: [👔 × _]  →  [👔 × 🍺]
```

**検出条件**: 制約ペアの一方が確定 → もう一方を制約に従い確定

---

### レベル2 ― 複合推理（複数ステップの連鎖）

レベル1で解けない部分に、これらが必要なパズルを **中級** とする。

---

#### ⑤ 端点バランス (Endpoint Balance)  ★ユーザー発見パターン

行/列の一方の端に同じ記号が2つある場合、反対の端は必ず逆の記号になる。

```
[👔 👔 _ _ _ _]  →  [👔 👔 _ _ _ 🍺]
```

**推論の根拠**:
1. もし反対端が 👔 なら → 👔 は3個（位置0,1,5）
2. バランスルールより残り3セル（位置2,3,4）は全て 🍺
3. 位置2はダブルブロック②ですでに 🍺
4. → 位置2,3,4 が 🍺🍺🍺 = **3連続違反** ❌
5. ∴ 反対端は 🍺 に確定 ✅

**一般化**: 逆向き `[_ _ _ _ 🍺 🍺]` → 先頭は 👔

**検出条件**:
- `grid[0] == grid[1] != EMPTY`  →  `grid[5]` を逆に確定
- `grid[4] == grid[5] != EMPTY`  →  `grid[0]` を逆に確定

> **メモ**: このパターンは単発強制（①②③）では検出できないが、
> 2段の論理推論（バランス → 3連続違反の背理）で確定できる。
> 仮置きとは異なり「論理的必然」である。

---

#### ⑥ 制約×バランス (Constraint × Balance)

`=` 制約の2セルが同じ行/列にある場合、その2セルは「同じ記号を2つ消費」するため、
残りのバランスに連鎖的に影響する。

```
行: [_ = _ _ _ _]  （pos0 と pos1 が = 制約）
→ 2セットが同じ記号 → 残り4セルに1個の同記号 + 3個の逆記号
→ 残り4セルのパターンが大幅に絞られる
```

---

#### ⑦ 連鎖推論 (Chain Deduction)

単発強制が連鎖して、複数ステップで別のセルを確定する。

```
例：
(2,0) が① により 👔 確定
  → ④ 制約= により (2,1) も 👔 確定
    → ① バランス完了で (2,2)〜(2,5) の残りが確定
      → ② ダブルブロックで列方向に別セルが確定
```

---

### レベル3 ― 仮置き（試行錯誤）

**上記①〜⑦を全て適用してもなお空セルが残る場合のみ**使用。

---

#### ⑧ 仮置き (Hypothesis / Trial & Error)

空セルに仮の値を置き、矛盾が生じれば逆の値が正解と判断する。

```
(r,c) に 👔 を仮置き
  → ①〜⑦ を再度全適用
  → 矛盾が発生  → (r,c) は 🍺 と確定
  → 矛盾がなく完成 → そのまま採用
```

> **設計方針**: 定時退社タンゴでは **⑧仮置きが必要なパズルは採用しない**。
> 理由: 達成感の質が下がる・ヒント機能が作れない・難易度が「理不尽」になる。

---

## 3. 難易度分類

| 難易度 | 必要な手筋 | 解いた感覚 |
|--------|-----------|-----------|
| **初級** | ①②③④のみ | 1手1手が自然に見つかる |
| **中級** | ⑤⑥⑦が必要 | 少し広い視野で考える必要がある |
| **上級** | ⑦の長い連鎖 | 頭の中で複数ステップを追う必要がある |
| **❌NG** | ⑧が必要 | 採用しない |

## 4. ソルバー実装方針

### 現在の実装（`validate-puzzles.js`）

```
applyForcedMoves(grid):
  繰り返し:
    全空セルに対して canPlace(SHIRT) と canPlace(BEER) を試行
    どちらか一方しか置けない → 強制確定
    両方置けない → 矛盾（null返却）
  変化がなくなるまで繰り返す
```

**現在の問題点**: ⑤端点バランスなど「2段推論」パターンが
単発チェックでは検出できず、バックトラッキングに頼っている。
→ パズルが誤って「仮置き必要=NG」と判定される可能性がある。

### 今後の改良方針

1. 各パターン（①〜⑦）を**明示的な関数**として実装する
2. `solveWithTechniques(grid)` が「どのパターンを何回使ったか」を記録する
3. 使用パターンのセットで難易度を自動判定する
4. ヒント機能に「今はこのパターンを使います」と案内できるようにする

```javascript
// 将来の実装イメージ
function solveWithTechniques(grid, constraints) {
  const usedTechniques = new Set();
  let changed = true;
  while (changed) {
    changed = false;
    changed |= applyBalanceCompletion(grid);    // ①
    changed |= applyDoubleBlock(grid);          // ②
    changed |= applySandwich(grid);             // ③
    changed |= applyDirectConstraint(grid);     // ④
    changed |= applyEndpointBalance(grid);      // ⑤
    changed |= applyConstraintBalance(grid);    // ⑥
    // ⑦ 連鎖は①〜⑥の繰り返しで自動的に発生
  }
  return { solved: isFilled(grid), techniques: usedTechniques };
}
```

## 5. 参考：難解パズルの事例

### Reddit投稿（2025年1月）

URL: https://www.reddit.com/r/puzzles/comments/1i8y3b2/cant_logically_solve_linkedin_tango_puzzle/

> ※ Redditはスクレイピング制限があり直接取得できず。ブラウザで確認のこと。

ユーザーが「論理的に解けない」と感じて投稿したLinkedInのTangoパズル。
**最終的にはロジックのみで解けることが判明**（コメントで解法が共有された）。

これは「仮置きが必要に見えるが実は不要」という典型的な高難度パズルの事例。
おそらく⑤端点バランスや⑦連鎖推論など、**知らないと気づけない複合パターン**が鍵になっている。

→ パズル設計の参考：「難しく感じさせるが、気づけば解ける」がユーザー体験として最高。
→ ヒント機能で「使うべきパターン名」を案内することで、達成感を損なわずサポートできる。

### LinkedIn公式の主張 vs 現実

| 主張 | 内容 |
|------|------|
| LinkedIn公式 | 全パズルは演繹のみ（仮置き不要）で解ける |
| Medium記事 (Jeff Foster) | 最難パズルは1セル+5制約で構成可能 |
| Reddit事例 | 一見「論理不可能」に見えるが最終的には演繹で解ける高難度パズルが存在 |

**結論**: 仮置きが「必要に見える」のは、複合パターン（⑤〜⑦）を知らないから。
パターンを知っていれば全て演繹で解ける設計が可能であり、それを目指すべき。

→ **定時退社タンゴでは、各難易度でどのパターンが必要かをヒント機能で案内する**ことで、
  ユーザーが「解けた！」と感じる体験を設計する。
